# Hardening Plan — evidence ledger and task list

This file is the **execution plan and evidence ledger** for the "best in every
category, provably" effort. `IMPROVEMENTS.md` remains the historical defect
record; this file tracks what is *proven*, what is *measured-but-inconclusive*,
and what is *not yet established*.

Rule for this document: **no number appears here that cannot be regenerated by a
command in §6.** Where a measurement was too noisy to support a claim, it says so.

## 3. Open findings

### 3.1 Wall-clock measurements are not reproducible to better than ~±7%

Nine PROC8 runs on identical code and corpus:

```text
35.68  35.82  35.91  37.66  38.20  40.26  41.87  43.00  49.40
```

A 13% spread. Consequences:

* Any timing claim finer than ~±7% is noise and must not be reported as a win.
* `reproduce_metrics.py` currently takes **one** sample, so its throughput row is
  not a reproducible metric. **This is the highest-priority fix** — without it we
  cannot tell a real 5% improvement from scheduling jitter.
* The `41.87` outlier was a real regression (reverted traversal cache, §3.2).

### 3.2 Reverted: cached AST traversal

Goal: ~50 rules each re-walk the same function AST, and traversal machinery
measured ~48% of CPU. Implementation cached the BFS node list per node and
shadowed the `ast` name inside `python_analyzer.py` only.

**Measured 41.87 s vs 35.91 s — 17% *slower*, and one test failed.** Cause:
`ast.walk` is lazy and rules `break` early, so materialising the list does strictly
more work. Reverted. Lesson recorded because it is a general trap: replacing a
lazy traversal with a cached eager one is only a win when callers consume the
whole sequence.

### 3.3 Throughput cost is architectural, not a hot spot

* Hottest single function: **0.93 s of 76 s** across 525 functions — the profile is flat.
* `analyze_python` totals 43.9 s for 188,958 LOC; largest single file 2.23 s.
* The slowest file (`topics.py`, 840 KB, 16,940 lines) has **163 AST nodes** — it is
  one giant string literal, so its cost is line-scanning regex rules, not AST work.
* Conclusion: the gap is *many analysis passes per line* vs Semgrep's lighter
  single pass. Closing it needs **fewer passes** (T10), not micro-optimisation.

### 3.4 Triage narration — resolved

Narration appeared in terminal output despite the `console.is_terminal` gate.
**Explanation:** the terminal is a TTY, so narration is *allowed* there — that is
what the gate is for. It appeared only because the harness was itself started from
an interactive terminal. The piped case is the one that matters, and
`tests/test_cli_output_hygiene.py` now asserts a captured scan emits no narration
while still reporting its findings (T9).

### 3.5 Profile cumulative times are unreliable in this codebase

`pstats` reported `__enter__` cumulative 144 s and
`_collect_python_guard_kinds_for_line` 124 s inside a 76 s run — impossible for
non-recursive functions. **Read `tottime`, not `cumtime`, when profiling here.**
Two optimisation attempts were misdirected by trusting cumulative numbers.

## 4. Task list

Format: **acceptance criteria** are the definition of done. `[ ]` open, `[x]` done.

### Tier 1 — turns "probably fine" into "proven"

* [x] **T1 · Reproducible throughput measurement.** ✅ **Done.**
  `measure_throughput()` takes 5 samples and reports "median (min--max) plus spread
  and the raw sample list; `EVIDENCE.md` carries the caveat that any delta smaller
  than the spread is noise.
* [x] **T2 · Provenance pinning.** ✅ **Done.**
  Manifest records `git_revision`, `git_dirty`, and a sha256 digest of `rules/`
  alongside the corpus digests.
* [x] **T3 · SARIF 2.1.0 validation.** ✅ **Done — and passing.**
  `tests/test_sarif_validation.py` (8 tests) validates version, `$schema`,
  driver, required result fields, location/region shape, `startLine >= 1`, and
  ruleId linkage. **The emitted SARIF is structurally valid**; the risk was
  unverified, not broken.
* [x] **T4 · Cache equivalence.** ✅ **Done — and passing.**
  `tests/test_cache_equivalence.py` scans the same tree cold then warm in one
  shared HOME and asserts identical `(file, line, rule_id, cwe, severity)` sets.
  **A warm cache does not change findings.**
* [ ] **T5 · Real-CVE recall inside the harness.**
  The 82-case CVE corpus (currently run by hand: 98.78% recall, 96.43% precision)
  must be a `reproduce_metrics.py` step. *Done when:* the CVE figure appears in
  EVIDENCE.md and is regenerated by the script.

### Tier 2 — breadth credibility

* [x] **T6 · Per-language recall table.** ✅ **Done — and verified.**
  The harness derives recall per language from the ground truth plus the miss
  list. Measured: **python 14/14, java 6/6, csharp 3/3, go 3/3, javascript 9/10**.
  The one miss is `javascript/ssrf_axios.js` (expected CWE-918, reported CWE-400
  and CWE-79). The aggregate 97.2% is therefore *not* uniform across languages,
  which is exactly why this table exists.
* [ ] **T7 · Cross-platform parity job.** Same corpus, same expected findings on
  Windows + Linux, 3.9 + 3.13. *Done when:* CI fails on any finding-set divergence.
* [ ] **T8 · CWE coverage against CWE Top 25.** Replace "35+ CWE types" with a
  checkable coverage statement.
* [x] **T9 · Triage narration gate verified.** ✅ **Done.**
  `tests/test_cli_output_hygiene.py` drives the real CLI with captured streams and
  asserts no narration, plus a second test that the findings still appear so the
  gate cannot pass by silencing the scanner. See §3.4.

### Tier 3 — closing the throughput gap

* [ ] **T10 · Single-visitor rule engine.** Run the `_rule_*` catalog from one AST
  traversal instead of ~50 independent `ast.walk` passes. This is the only change
  with the headroom to beat 6,144 LOC/s. Large; must be landed rule-group by
  rule-group with the labelled corpus as the regression guard.
* [ ] **T11 · Update `WORLD_CLASS_SCORECARD.md`** with measured numbers, marking
  throughput ❌ honestly.
* [x] **T12 · Commit.** ✅ **Done.** Two commits were rewritten as one clean
  commit `436131d8` (the first attempt was made by piping a PowerShell here-string
  into `git commit -F -`, which prepended a UTF-8 BOM to the subject; both commits
  were unpushed, so history was rewritten safely and the BOM verified gone).
  Not tagged, and **not pushed** — `main` is ahead of `origin/main` by one.

## 5. Do-not-do list

Explicitly rejected, because each would move a metric without making the product
better:

* Weakening or deleting rules to raise precision.
* Editing the clean corpus to raise the precision figure.
* Reporting a single-shot wall-clock time as a throughput result.
* Presenting aggregate recall as if it were per-language.
* Citing a timing delta that sits inside the ±7% noise band as a win.

## 6. Reproduce

```bash
pip install -e ".[dev]"
python benchmarks/reproduce_metrics.py        # writes results/EVIDENCE.md + manifest.json
pytest tests/ -q
ruff check .
```

`EVIDENCE.md` is generated, never hand-edited. The CI `metrics` job runs the same
script and fails the build when recall or clean-code precision regress.
